# Plan: a site a first-time visitor can follow (2026-11-27)

Status: **accepted 2026-11-27.** The owner took every recommended answer
(see "Owner decisions").
Written by the manager from the brief of 2026-11-27.

## The goal

A visitor who has never seen the repository can tell, from the site alone:
what this is, what to type, how a task travels from words to a reviewed pull
request, who does which job, which skill calls which, what has been done, and
how to reach the owner.

## Where the site lives today

- GitHub Pages serves the `docs/` folder of `main`.
- There is one page, `docs/skill-graph.html`. It is generated by
  `scripts/graph.mjs` from `scripts/graph.template.html`, and CI fails when it
  is stale. Nobody edits it by hand.
- The site root returns 404, because `docs/` has no `index.html`.
- The page opens on the graph. The explanation is a side panel.

## The decision

1. **Explain first, explore second.** The site root becomes a short page in
   plain words. The graph stays, one click away, for people who want to dig.
2. **Everything is generated** from the files the agents read: the skills'
   metadata, `docs/plans`, and the pinned extras. A page that is written by
   hand drifts, and the project's rule is that it must not.
3. **The owner picks the first screen from two rough versions** before the
   real page is built. "More intuitive" is a matter of taste, so it is settled
   by looking, not by a description.
4. **No build step, no framework, no new dependency.** Plain files in `docs/`.

## Order and cost

- T1 first, then the owner's pick. T2 can run beside T1: they share no file.
- T3, T4 and T5 share the templates and run in sequence.
- Six small PRs. Each is reviewed by a model from another provider, and the
  reviewers alternate between providers.
- One more generated file (`docs/index.html`) means one more file that
  conflicts when two plan or skill PRs are open at once. The fix for that is
  tracked separately.

## Owner decisions (answered 2026-11-27)

1. **The contact block** shows a link to open an issue and a link to the
   owner's GitHub profile. Both are already public. Nothing else is published
   unless the owner names it.
2. **The visitor** is a developer arriving from the GitHub link who has never
   seen the repository.
3. **The record of what was done comes from the plans** (T2), not from a
   hand-written changelog.
4. **Every plan is shown**, newest first, older ones folded.
